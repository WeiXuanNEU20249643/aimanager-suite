# Sprint 3 API 契约

Sprint 3 继续使用 `/api/projects/{project_id}` 项目作用域、同源 HttpOnly Cookie、`X-Requested-With: aimanager` 写请求校验、snake_case 字段和统一失败结构。所有排期、任务、成员容量和重排记录均在每次请求时按当前项目成员关系授权。

## 统一排期查询

`GET /planning` 返回甘特图和成员任务图共同使用的快照：

- `plan`：项目级共享排期版本、最近更新时间和操作者。
- `horizon`：当前有效任务的最早计划开始、最晚计划结束及自然日跨度。
- `tasks`：未取消的真实任务，字段与任务列表/详情一致，包含任务 `id`、`version`、状态、负责人、计划日期、工时、锁定标记、依赖和取消口径。
- `unscheduled_task_ids`：缺少计划开始或结束日期的任务。
- `members`：有效成员和仍被任务引用的已移除成员；包含容量、工作量、负荷率和技能标签。
- `unassigned`：未分配任务数与工作量。
- `cancelled_count`：保留历史但不进入当前甘特和未来容量的取消任务数。

工作量优先使用非零剩余工时，否则使用 `max(估算工时-实际工时, 0)`。计划期容量按成员每周容量和当前计划跨度折算；缺少容量时返回 `null`，不以任务数量代替。

## 需求影响与重排

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/requirements/{req_id}/planning-impact` | 返回直接关联任务、传递后继、可重排项、保留项、需求版本、共享排期版本和最近记录 |
| GET | `/requirements/{req_id}/planning-runs` | 返回最近十次已应用或因冲突未应用的排期记录 |
| POST | `/requirements/{req_id}/replan` | 仅内置管理员；确认影响并执行原子重排 |

重排请求：

```json
{
  "requirement_version": 2,
  "plan_version": 17,
  "reason": "已确认工作量和依赖变化"
}
```

服务端同时校验需求版本和项目排期版本。任一过期返回 409，客户端必须刷新影响清单，不得用旧版本覆盖新任务或容量数据。

重排规则：

- 只自动移动未取消、状态为“待办”且未锁定的受影响任务。
- 按无环依赖顺序、负责人可用期、每周容量和既有承诺任务计算工作日计划。
- 已完成、进行中、待验收或锁定任务保留日期；若与后继或前置关系冲突，返回可定位提醒。
- 缺少负责人、有效容量、前置结束日期或超出成员可用期属于阻断冲突，`applied=false`，任务日期、状态和验收结论均不发生部分更新。
- 超过任务截止日期作为警告返回；在无阻断冲突时仍可应用，并保留影响清单供人工处理。
- 成功后写入新的共享排期版本、任务旧新日期、任务版本、需求版本、操作者、时间、原因和 append-only 任务事件。

## 同步语义

任务创建、编辑、负责人/状态/排期变化、依赖变化、取消/重开、需求变更、成员容量或成员关系变化都会推进项目共享排期版本。成员任务图每 5 秒重新读取 `/planning`；网络失败保留当前画面并提示未同步，恢复后重新读取，前端不缓存写权限，也不会把旧快照回写服务端。
