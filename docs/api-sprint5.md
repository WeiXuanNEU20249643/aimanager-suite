# Sprint 5 API 契约

所有路径均位于 `/api/projects/{project_id}`，需要有效会话、项目成员身份和 `X-Requested-With: aimanager`。响应禁止缓存。AI 凭据只从服务端环境读取，任何响应、事件或调用记录都不返回 API Key。

## 权限

- `ai.read`：读取配置状态、调用记录、模型输出和审查记录。观察者默认只有此权限。
- `ai.write`：发起调用、修改草案和否决草案。内置管理员、成员默认具备。
- `ai.apply`：确认应用草案。应用时还要具备对应业务权限：PRD 拆解需要 `requirement.write` 和 `task.write`，智能排期需要 `task.write`，预测确认需要 `task.read`。
- 每个受保护请求都重新读取当前成员身份；模型调用结束后再次核验权限，调用期间撤权时不保存结果。

## AI 中心和记录

### `GET /ai`

返回服务配置状态、当前共享数据版本、最近 50 条调用记录、待审查数和失败数。配置仅包含 `configured`、模型标识和超时秒数。

### `GET /ai/runs/{run_id}`

返回当前项目内的一条调用记录。记录包含能力类型、输入版本、输入、模型、去凭据后的服务地址、状态、原始输出、修改后输出、当前有效输出、错误和只追加审查历史。跨项目编号返回 404。

状态为：

- `draft`：等待人工审查；
- `applied`：已确认并执行；
- `rejected`：已否决且未修改业务数据；
- `failed`：调用或结构校验失败，保留输入但未产生可应用草案。

## 生成草案

### `POST /ai/prd-breakdowns`

请求：

```json
{"source_name":"支付模块 PRD v1.2","prd_text":"PRD 原文"}
```

服务端真实调用配置的模型，要求返回故事角色、故事、可测验收条件、PRD 来源段落、优先级、任务、依赖、技能和小时估算。临时任务编号必须唯一，依赖必须引用本次结果且不能自依赖或成环。来源段落不能在原文定位的故事移入 `unsupported_items`，不会被应用。

### `POST /ai/forecasts`

请求：

```json
{"as_of_date":"2026-10-12"}
```

日期可为空，默认使用 Asia/Shanghai 当日。服务端读取未取消的已完成任务；估算和实际工时均大于 0 的记录才是有效样本。样本不少于 3 条时使用 `actual_hours / estimated_hours` 的中位数校准剩余工时，再按前置依赖和成员周容量推算日期。模型只能解释确定性证据，不能改写样本、系数、任务计算或日期。

### `POST /ai/schedules`

请求：

```json
{"start_date":"2026-10-12"}
```

服务端按需求优先级、任务依赖、剩余工时、任务所需技能、成员技能、周容量和可用期生成建议。待办且未锁定的任务可移动；进行中、待验收、已完成和锁定任务进入 `preserved`。错误级冲突将 `blocked` 置为 `true`，禁止应用。模型只解释每条确定性建议的理由和取舍。

三个生成端点成功返回 201。未配置返回 503，连接失败返回 503，超时返回 504，额度或频率限制返回 429，模型结构错误返回 502。失败响应仍是已持久化的 `failed` 记录。

## 审查

### `PATCH /ai/runs/{run_id}`

```json
{"version":1,"output":{},"reason":"补充验收条件"}
```

仅 `draft` 可修改，并检查草案版本。PRD 拆解可修改结构化故事和任务，但仍须通过全部结构、来源和依赖校验。预测的计算证据、排期的确定性建议不可直接修改；只能修改对应 AI 解释。每次修改写入只追加 `ai_reviews`。

### `POST /ai/runs/{run_id}/reject`

```json
{"version":1,"reason":"来源不足"}
```

将草案标记为 `rejected` 并记录理由，不改变需求、任务、容量或排期。

### `POST /ai/runs/{run_id}/apply`

```json
{"version":2,"reason":"已核对来源与差异","operation_id":"client-generated-unique-id"}
```

应用前依次检查：AI 与业务权限、草案状态和版本、当前共享数据版本、结构和业务约束。`operation_id` 在项目内唯一；同一草案使用相同标识重试时返回已应用记录，不重复创建或更新。标识用于另一草案返回 409。

- PRD 拆解：原子创建独立需求、关联任务和任务依赖；工时写入估算和剩余工时，技能写入任务所需技能，Sprint 为 S5。
- 进度预测：记录人工确认，不修改任务或计划值。
- 智能排期：原子更新建议中的负责人和计划日期；锁定或非待办任务不会被移动。更新后共享计划版本推进，甘特和成员任务图读取相同任务数据。

失败、否决、权限不足、草案版本冲突或共享数据版本冲突均不修改源业务数据。

## 任务技能

`PATCH /tasks/{task_id}/plan` 在 Sprint 5 新增 `required_skills`：

```json
{
  "estimated_hours": 8,
  "actual_hours": 0,
  "remaining_hours": 8,
  "planned_start": null,
  "planned_end": null,
  "plan_locked": false,
  "required_skills": ["后端", "数据库"],
  "version": 3,
  "reason": "补充排期约束"
}
```

技能大小写不敏感地去重校验。智能排期仅选择技能全集覆盖任务要求且具有正数容量的有效非观察者成员。
