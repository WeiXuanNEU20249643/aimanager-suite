## 执行环境与结果

本机 Windows、Python 3.14（项目 `.venv`）、Node.js 24.18.0，FastAPI 0.136.1、Pydantic 2.12.5，React 19.3.0、Vite 8.3.0、Playwright 1.62.1／Edge 无头浏览器。前端依赖已锁定具体版本并提交 package-lock 文件到工作目录。

- 后端：`python -m unittest discover -s tests -v`，13 组测试全部通过（最终一轮 14.795 秒）。覆盖正常、拒绝、边界、并发、数据持久化、原子失败和空数据库 CLI 初始化；执行结果见本任务工具输出。
- 前端：`npm ci` 后 `npm run build` 成功。预览页面延迟加载，正式入口和原图表模块分开打包。
- 浏览器：`PLAYWRIGHT_CHANNEL=msedge npm run test:e2e` 成功。真实 HTTP 请求连接 FastAPI／临时 SQLite，测试管理员、成员、观察者三种独立会话。
- 浏览器主路径：登录→添加成员→登记需求→搜索／深链接／刷新→从需求创建任务→列表／看板切换→成员修改及提交→管理员确认完成→刷新重读→切第二项目→移除成员→原成员失权→退出并重访受保护地址。
- 浏览器额外检查：前进后退恢复页面，模拟网络断开后显示错误且清除旧详情，恢复后重新读取；无未捕获页面异常。
- 视觉检查：需求页面、1480 宽看板和 1280 宽看板截图，沿用现有视觉；窄桌面视口仍保留四列，必要时在看板内部横向滚动。测试截图仅使用明确标识的测试样本。

测试中发现并修复：Windows SQLite 连接未关闭导致临时库锁定；下拉表单的可访问标签不明确；测试登录步骤需要等待项目路由就绪；网络失败测试的拦截规则需同时覆盖列表和详情请求。数据库事务在响应前完成提交，连接在请求结束时关闭。

## 数据及证据边界

API 用例每次创建临时数据库。浏览器测试通过 stdin 传递随机密码，日志和截图不包含密码；用完停止独立测试服务并清理测试库。正式库没有导入测试业务记录，也没有默认口令。首个管理员与项目按 README 由操作者初始化。

`events` 从 S1 保存真实发生时间、操作者、前后值、原因及操作标识，不补写虚构历史；数据库升级重复执行保持数据。自动化测试会注入存储失败验证回滚，不影响正式库。

## 10 分钟人工复演

1. 按 README 初始化管理员、成员、观察者账号，创建项目；管理员登录并把已有账号加入项目。
2. 登记包含标题、描述、来源的需求，复制详情地址并刷新确认稳定。
3. 从需求创建任务，分配成员、截止日及 Sprint，切换列表与看板核对任务编号和来源。
4. 成员登录，编辑任务并推进至进行中、待验收；确认没有最终验收按钮。
5. 管理员刷新任务，核对来源需求，勾选验收确认并完成任务，切换视图核对状态。
6. 观察者登录，只读查看；管理员移除该账号后刷新验证失权。检查最后一名管理员不可移除或降级。
7. 切换第二项目验证数据隔离；退出后用原地址访问应返回登录界面。
