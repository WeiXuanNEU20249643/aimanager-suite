# Sprint 2 实施与验证记录

日期：2026-09-20。范围以《爱管理241016 交付物3 项目规划方案 三阶段融合版》为准：Must 为 US18、US19、US09、US33、US11、US27、US28、US05；已排 Should 为 US07、US21、US30。实现继续使用现有 React、FastAPI、SQLite 工程和既有视觉组件，没有另建项目或整体改版。

## 正确范围实现结果

| 故事 | 实现与自动化证据 |
| --- | --- |
| US18 | 需求编辑必须提交原因和当前版本；成功后版本递增并保留旧快照；旧版本提交返回 409；仅将有效关联任务标记待复核，不自动改变状态或 Sprint |
| US19 | 支持 Must、Should、Could、Won't 与非空验收条件；列表、详情和任务源需求区域显示一致；修改进入版本历史 |
| US09 | 同项目依赖新增与解除、人工阻塞、原因和操作者记录；拒绝自身、重复、跨项目和循环依赖；两类阻塞分别保存 |
| US33 | 任务保存估算、实际、剩余工时、计划开始／结束、截止日和锁定标记；成员保存可用时段、每周容量和技能；非负、日期顺序、版本冲突均由服务端校验 |
| US11 | 任务详情显示只读关键变更历史，包含操作者、实际时间、前后值和原因；按项目授权查询；缺少创建事件时明确报告，不按当前快照补造 |
| US27 | 仅内置管理员可填写原因取消任务；保留最后状态、取消人、时间和历史；取消后所有任务写入与流转被拒绝，不提供恢复或物理删除；统计单列并排除有效分母 |
| US28 | 仅内置管理员可把已完成任务重开为进行中且原因必填；原验收事件保留并新增重开事件；取消任务不能重开；完成率实时减少，北京时间所属自然周重开数增加 |
| US05 | 四状态数量来自有效任务，取消任务单列；状态项可进入同项目同口径列表；空项目显示 0／暂无任务，刷新后与列表一致 |
| US07 | 负责人、状态、关键词和取消范围可组合或清空；列表、看板与概览复用同一查询；空结果、加载失败和越权分开处理 |
| US21 | 需求详情展示关联任务、负责人、状态和取消标记；有效数及已完成数实时重算；无关联任务明确提示 |
| US30 | 完成率按有效已完成任务数／有效任务总数保留一位小数；待验收不计完成，取消项排除，空分母显示暂无任务 |

## 上一版 Sprint 2 工作的保留价值

上一轮已经实现的需求版本、MoSCoW 优先级、验收条件、任务依赖／阻塞、组合筛选、需求进展和完成率，直接覆盖了新基线中的 US18、US19、US09、US07、US21、US30，并为本轮 US11、US27、US28 的事件和统计口径提供了可复用基础。

以下实现不属于新基线的已排 Sprint 2，但与融合版规划一致，作为候选能力保留：

- US10 里程碑关联与完成情况：Should，候选未排期。它复用了有效任务、取消排除和完成率口径，为阶段节点核对提供现成入口。
- US22、US23、US25 自定义角色、模块权限和即时分配：Should，候选未排期。它强化了项目隔离和最小权限，并已确保重开、取消、最终验收等敏感操作不能被自定义角色获得。
- US20 任务源需求改绑：Could，候选未排期。它已实现原因、前后来源和事件记录，提前补强任务追溯。

这些能力未删除，也没有被计入本轮八条 Must 的完成数量。

## 数据库升级

SQLite `PRAGMA user_version` 从 2 增量升级到 3。任务表新增工时、计划日期和锁定字段；新增成员容量表。版本 2 中的需求版本、依赖、里程碑、自定义角色和取消预留字段原样保留。迁移只新增表、列和索引，不删除业务记录、不覆盖事件、不导入 Mock 数据；重复启动不会重复迁移。

## 人工复演

1. 修改需求并查看旧版；确认关联有效任务出现待复核，状态和 Sprint 不自动变化。
2. 给任务登记估算、实际、剩余工时、计划日期和锁定标记；给成员登记周容量、可用时段和技能标签。
3. 添加前置依赖与人工阻塞；验证自身、跨项目和循环依赖被拒绝。
4. 完成任务后填写原因重开；核对完成率下降且原验收事件仍在历史中。
5. 取消待办任务和已完成任务；核对最后状态保留、取消项单列、有效分母减少，取消后编辑和重开均被拒绝。
6. 按负责人、状态和关键词组合筛选；核对列表、看板和状态概览采用同一口径。
7. 用观察者查看任务历史；确认事件只读、跨项目被拒绝，缺失记录不会由当前快照补造。

自动化通过不等同于团队人工签认。当前目录没有 Git 元数据，因此没有远端 CI、提交号或 PR；非作者复验、产品负责人接受及课程要求的签字仍需团队完成。
