## TC41 AI 需求拆解与估算

- 真实向本地 HTTP 模型兼容端点发送结构化请求，验证模型标识和服务端 Authorization 头；响应和页面不包含凭据。
- 正常 PRD 生成角色、故事、AC、来源段落、任务、依赖、技能和工时；编辑后通过人工理由保存新草案版本。
- 无法在 PRD 定位来源的故事进入无来源清单，不参与应用；歧义单列。
- 确认后原子创建一个独立需求、两个关联任务和一条依赖；刷新后能从统一需求／任务接口读取。
- 格式异常、超时、429 均形成失败记录，需求、任务和依赖数量不变。

## TC42 进度预测

- 零到两条有效历史记录时显示“历史不足3条”，校准系数为 1，结果标记为基准计划。
- 三条记录的实际／估算比分别为 1、1.5、1.5，中位数为 1.5；10 小时剩余任务校准为 15 小时，样本和任务计算均返回页面。
- 预测日期由服务端依赖和容量计算产生，AI 只返回引用这些证据的解释。
- AI 解释返回非 JSON 时记录 `invalid_format` 失败，不把缺失解释伪装成预测成功。
- 确认预测仅保存审查决定，不改变任务快照。

## TC43 智能排期

- 任务所需“后端”“前端”技能与成员技能匹配；依赖任务的建议开始日晚于前置任务建议结束日。
- 锁定任务出现在保留清单，应用前后完整任务快照一致。
- 应用后负责人和计划日期写入同一任务记录，甘特页读取到确认结果。
- 所需“量子编译”技能无人满足时返回 `skill_or_capacity_missing` 错误冲突，`blocked=true`，应用返回 409 且任务不变。
- 生成逻辑按容量把同一成员的任务顺序排列，不制造并行超容量承诺；输出明确“不承诺全局最优”。

## TC47 AI 建议审查与应用

- 记录输入、输入版本、模型、服务地址、时间、原始输出、修改输出、状态、错误和审查理由。
- 观察者可以读取但不能调用、修改、否决或应用；成员需同时满足相应业务写权限。
- 模型调用期间会释放数据库写锁，返回后重新开启事务并再次核验权限。
- 修改、应用和否决写入只追加审查记录；原始模型输出不被覆盖。
- 确认应用前检查共享数据版本；调用后业务数据变化时返回 409。
- 同一 `operation_id` 重试不会重复创建需求、任务或依赖。

## 人工复验建议

1. 用实际目标模型和非生产测试项目配置四个 AI 环境变量，确认其支持 JSON Object 响应。
2. 输入含明确段落、歧义和无来源诱导语的 PRD，逐项核对来源清单后再应用。
3. 为两名成员配置不同技能、容量和可用期，检查排期差异、锁定项、技能冲突及甘特／成员图同步。
4. 在模型调用过程中撤销调用人权限，确认返回结果不被保存。
5. 在草案生成后修改任一任务或容量，再确认旧草案，检查 409 和零写入。
